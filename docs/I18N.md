# Multilingual support (uz / ru / en)

## 1. Before this change

- One typed Uzbek dictionary, `src/i18n/uz.ts`, imported as a constant `t` in 27 files
  (`t.nav.home`, `t.collection.results(n)`). Most UI text was already centralised.
- Uzbek text was still hard-coded in several places: validation messages
  (`validation/checkout.ts`, `features/products/admin/productInput.ts`), CSV import errors
  (`features/csv/productCsv.ts`), image upload errors, Supabase error mapping, `money.ts`
  ("soʻm"), `brand.ts` (tagline, city, hours), the "One size" label and taxonomy names.
- Validation messages were computed once at module load, so they could never change language.
- No language state, `<html lang>` fixed to `uz`, page titles not translated.

## 2. Supabase product schema (before)

- `products`: `name`, `description` (Uzbek) plus shared fields (price, sizes, color_ids,
  gender, delivery days, flags, status). `product_variants` and `product_images` hang off it.
- `categories` / `colors`: id + Uzbek `name`.
- `order_items` snapshots `product_name`, `color_name` and the price at order time.
- `admin_save_product(p_id, p jsonb)` writes a product, its variants and images in one
  transaction. `place_order()` re-prices from `products`.

## 3. Migration (`supabase/migrations/20261118083718_product_translations.sql`, applied 2026-11-18)

- New table `product_translations (product_id, locale in ('ru','en'), name, description)`,
  primary key `(product_id, locale)`, `on delete cascade`. Uzbek stays in `products.name /
  description` as the required source text, so `place_order`, slugs and existing rows are
  untouched. Prices, images, sizes etc. are never duplicated.
- RLS mirrors `product_images`: anyone reads translations of active products, admins
  insert / update / delete.
- `categories` and `colors` (small fixed lookup tables) get `name_ru` and `name_en`, seeded
  with real translations.
- `admin_save_product` also upserts/deletes translation rows from `p.translations`.
  An empty ru/en name removes that translation (the storefront falls back to Uzbek).
- `order_items` snapshots are not changed: historical orders keep the Uzbek names they
  were placed with.

## 4. Frontend architecture

- `i18next` + `react-i18next`. Strings in `src/locales/{uz,ru,en}/translation.json`,
  Uzbek is the default and the fallback language, so a missing ru/en key shows Uzbek,
  never a key.
- Language stored in `localStorage` (`store.lang`), applied without a reload; `<html lang>`,
  page title and meta description follow it.
- Components read text through `useTranslation()`. Validation returns message keys
  (with parameters) that are translated when rendered, so errors switch language too.
- Product/category/colour names go through `productName`, `productDescription`,
  `taxonomyName` and `sizeLabel` (`src/i18n/content.ts`), each falling back to Uzbek.
- Prices: `349 000 soʻm` / `349 000 сум` / `349,000 UZS`. Dates: `17.11.2026` (uz, ru),
  `17 Nov 2026` (en); chart month names come from the dictionaries.
- Language selector (`LanguageSwitcher`) in the storefront header, mobile menu and admin
  sidebar and admin login: a labelled group of toggle buttons (Tab + Enter/Space,
  `aria-pressed` marks the current language). Product editor tabs use arrow keys.
- Brand name `SARANG` is never translated.

## 5. Adding or changing text

- Add the key to all three files in `src/locales/`; `tests/i18n.test.tsx` fails if a key,
  plural form or `{{variable}}` is missing in any language.
- Keys are type-checked: `t('nav.hme')` is a TypeScript error.
- Never translate at module level (`const LABEL = t(...)` runs once, in the start-up
  language). Store the key and call `t(key)` while rendering.
- Order item names are historical snapshots and stay as they were (Uzbek).

## 6. Testing

- Unit: every key in uz exists in ru and en (and vice versa), no empty strings;
  fallback for missing product translations; money/date formatting per language;
  validation messages per language.
- Component: language switch re-renders without reload, persists in localStorage,
  checkout errors translated, `<html lang>` updated.
- Database: smoke test (rolled back) creating a product with translations, reading it as
  anon, removing one translation, placing an order and checking the snapshot stays Uzbek.
- Browser: every storefront and admin page in all three languages, refresh persistence,
  mobile menu selector.
